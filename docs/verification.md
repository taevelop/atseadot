## 자동 검증

```sh
npm test
npm run build
```

`tests/game.test.cjs`, `tests/keyboard.test.cjs`, `tests/virtual-controls.test.cjs`, `tests/typography.test.cjs`의 회귀 테스트 총 39개가 통과했습니다. `build`는 JavaScript 구문 검사와 이 테스트를 모두 실행합니다. 테스트는 실제 게임 스크립트를 Node VM에서 실행하며, 시간·난수·저장소·Canvas·DOM 환경을 대체합니다.

## 브라우저 검증

- 데스크톱 1258×622, 모바일 세로 390×844, 가로 844×390에서 확인했습니다. 가로 화면은 Chrome의 터치 에뮬레이션을 활성화해 화면 너비에 따른 배치까지 확인했습니다.
- 포획 수심과 화면 전환 검증에는 게임 상태를 준비한 뒤 실제 버튼을 누르는 방식을 사용했습니다. 자연 발생하는 입질을 기다리는 장시간 플레이 테스트는 포함하지 않았습니다.
- 첫 화면, 도움말, 도감 목록·상세, 포획 결과, 모바일 가로·세로 화면을 스크린샷으로 확인했습니다.
- 주요 조작 및 저장 복구 후 브라우저 JavaScript 오류는 0건이었습니다.
- Pages 응답 경로와 앱 아이콘은 기존 정적 배포 구조를 사용합니다. 이 검증은 로컬 실행을 대상으로 합니다.

## 모바일 가상 컨트롤러

- 왼쪽 원형 다이얼: 중앙 정지 영역, 8방향 이동, 손가락을 떼지 않는 방향 전환, 바깥쪽 가속, 누른 방향과 가속 상태 표시.
- 오른쪽 버튼: 82px 액션 버튼과 56px 가속 버튼. 액션은 포획·던지기·챔질·닫기·재개 상태에 맞춰 표시되며, 손가락을 뗄 때 중복 실행되지 않습니다.
- 다이얼과 액션·가속 버튼은 독립적인 포인터를 처리합니다. 다른 손가락을 떼어도 다이얼 입력을 취소하지 않습니다.
- 화면 회전, 앱 전환, 터치 취소 시 이동 입력과 버튼 캡처를 해제합니다. 메뉴·역할·일시정지 상태 전환 시 이전 이동 입력을 정리합니다.
- 한국어·영어, 320×640·390×844·568×320·844×390에서 화면 넘침과 게임 영역 가림이 없고, 버튼 터치 영역이 44px 이상임을 확인했습니다.
- Chrome의 실제 다중 터치 이벤트로 대각선 이동 중 포획, 드래그 방향 전환, 다이얼 밖으로 이동한 상태의 캡처, 가속 버튼 동시 누름, 터치 취소를 검증했습니다.
- 포획 결과가 손가락을 뗀 뒤에도 유지되고, 다이얼로 도움말 페이지를 넘길 수 있음을 확인했습니다. 450m에서 화면 회전 후 수심과 생물 상태도 유지됐습니다.
- 가상 컨트롤러 검증 후 브라우저 JavaScript 오류는 0건이었습니다. 실제 iOS·Android 기기 검증은 포함하지 않습니다.

## 가상 조작부 표시 범위

- 화면 너비 1024px 이하에서만 표시하고, 1025px 이상에서는 숨깁니다. 입력 장치 종류와 터치 지원 여부는 표시 조건에 사용하지 않습니다.
- Chrome에서 390·768·1024px 표시, 1025·1280px 숨김을 확인했습니다. 터치가 지원되는 데스크톱 조건에서도 숨겨지고 게임 캔버스가 전체 높이를 사용합니다.
- 1024px에서 다이얼을 누른 채 1025px로 전환하면 입력이 해제되고, 숨겨진 버튼에서 포커스가 빠져 키보드 조작이 이어지는 것을 확인했습니다.

## 모바일 한글 픽셀 글자

검증일: 2026-09-10. 사용자가 제공한 iPhone 16 Pro 화면의 한글 획 손상과 가독성 문제를 기준으로 개선했습니다.

### 적용 내용

- Galmuri11 웹폰트를 함께 배포하고 `@font-face`와 preload로 로딩합니다. 시스템 글꼴을 11px로 그려 알파 값 96 이하의 획을 삭제하던 처리를 제거했습니다.
- Galmuri11은 12px가 기준 크기입니다. 3배 크기로 먼저 렌더링하고 최근접 샘플링으로 원래 픽셀 격자에 맞춥니다. Windows Chrome에서 직접 12px로 그리면 반투명 가장자리가 남았지만 3배 샘플링에서는 검사한 글자의 알파가 0 또는 255로 유지됐습니다.
- 첫 프레임은 폰트 로딩 후 시작합니다. 로딩이 2초보다 오래 걸리거나 실패하면 기본 글꼴로 시작하며, 늦게 도착한 폰트는 글자 캐시와 현재 대사 줄바꿈을 갱신합니다. 바다와 진행 상태는 다시 생성하지 않습니다.
- 한글의 기본 그림자를 없애고 보조 글자를 밝게 조정했습니다. 줄 간격은 논리 화면에서 14px, 메뉴 행은 16px입니다. 긴 기록은 수심·수집 수 단위로 나눠 어두운 안내 패널에 표시합니다.
- 캔버스 메모리 크기는 CSS 크기와 기기 픽셀 밀도에 맞춥니다(밀도 상한 4). 게임 픽셀은 물리 픽셀의 정수 배율로 그리며 오른쪽·아래쪽의 한 칸 미만 여분만 잘라냅니다. 포인터 좌표에도 같은 배율을 적용합니다.
- 좁은 화면의 일시정지 표시는 상단 기록 아래에 배치합니다. 제목 화면 높이가 부족하면 큰 로고를 생략해 메뉴와 기록 공간을 확보합니다.

## 단축키 역할 정리

검증일: 2026-09-10.

### 변경 내용

- 방향키와 WASD로 이동합니다. 낚싯배에서는 A/D가 좌우 이동, W/S가 낚싯줄 깊이 조절이며 Shift 가속을 함께 사용할 수 있습니다.
- 도감 단축키는 G입니다. 시작 화면·플레이·다른 창에서 도감을 열고, 도감 목록이나 상세에서 다시 누르면 도감을 닫습니다. D는 이동에만 사용합니다.
- Space는 대사 표시 여부와 관계없이 그물·상자·낚시 액션을 실행합니다. Q/E는 도감 목록과 조작법의 페이지 이동에만 사용합니다.
- Z/Enter는 선택 또는 대사 표시·다음 대사 진행에 사용합니다. X/Esc는 상세에서 목록으로, 열린 창에서 이전 화면으로 돌아가며 플레이 중에는 대사를 먼저 닫습니다. 닫을 대사가 없으면 시작 화면으로 돌아갑니다. 배경화면 모드는 먼저 해제합니다.
- 포획 결과·조작법·도감 상세는 Z/Enter·D·Q로 닫히지 않습니다. 모바일 큰 버튼은 해당 화면에서 닫기 동작을 실행하며, 플레이 중 대사가 있어도 그물·낚시 액션을 표시합니다.
- Ctrl/Alt/Meta 조합과 문자 조합 중인 키 이벤트는 게임에서 처리하지 않습니다. 브라우저 기본 동작을 막지 않고 Shift 가속을 유지합니다.
- 한국어·영어 게임 안내와 README의 조작표를 새 배치에 맞췄습니다.

### 검증 결과

## 낚싯배 세 단계 (2026-09-18)

`feat/boat-behaviour`에서 배를 세 단계로 늘렸다. Node.js 24.15.0에서 `npm run build`가 **102개 테스트 모두 통과**했고, `git diff --check`도 통과했다. 화면은 `site/`를 정적 서버(localhost:8791)로 띄워 확인했다.

### 먼저 치수를 한곳으로 모았다

배의 폭·높이·선체 줄·낚싯대 자리·수면에 앉는 깊이가 코드 열일곱 곳에 흩어져 있었다. 두 번째 선체를 넣으려면 그 자리를 모두 찾아야 했으므로, `BOAT_TIERS` 한 곳에서만 읽도록 먼저 바꾸고 표가 한 줄일 때 기존 시험이 그대로 통과하는 것을 확인했다.

### 세 단계

| 단계 | 도안 | 크기 | 선체 줄 | 낚싯대 끝 | 이동 속도 |
| --- | --- | --- | --- | --- | --- |
| 기본 | `boat` | 54×34 | 24 | (52, 9) | 100% |
| 1단계 | `boat2` 롱십 | 61×33 | 24 | (58, 8) | 120% |

값은 700·1600코인으로 기존 장비 중 가장 비싸다. 보기만 달라지는 것은 외형 상품이지 장비가 아니므로, 단계마다 배가 실제로 더 잘 나가게 했다.
