## 이번 감사의 실행 근거

Node.js `v24.16.0`, npm `11.13.0`에서 `npm run build`를 실행했다. JavaScript 구문 검사와 기존 테스트 **39/39개가 통과**했다. 통과한 테스트가 새 기능의 완성을 뜻하지는 않는다.

`tests/helpers/game.cjs`로 실제 `game.js`를 실행하는 일회성 VM 재현도 수행했다. 저장소의 테스트 파일을 추가하거나 수정하지 않았다.

| 재현 | 현재 결과 |
| --- | --- |
| 일반 fish3 1마리와 희귀 fish3 1마리를 `caught()`로 포획 → 저장 → 재로딩 | `caught=2`, `rare=1`이지만 `hold=0`, `holdR=0`. `stocked=1`이어서 재로딩으로도 재고가 복구되지 않음 |
| 기존 저장 `caught.fish3=5`, `rare.fish3=2`를 최초 로딩 | 일반 3, 희귀 2로 이관됨. 재고를 1로 줄여 저장하고 다시 로딩하면 1을 유지함 |
| 실제 keydown/keyup으로 A/S 입력 | 화면은 `dive`를 유지하고 각각 왼쪽/아래로 이동함 |
| `controlAction('aqua')`, `controlAction('shop')` | 화면 변화 없음. 제목 메뉴도 기존 5개만 존재함 |
| 같은 상태에서 오리발 0단계/2단계로 `stepDiver(1, false)` 실행 | 수평 속도가 모두 `0.1419`로 같음 |
| 충돌 사이마다 `bump`를 해제해 상어와 20회 충돌 | `snap=20`이지만 체력 필드가 없고 계속 `mode='dive'`임 |

Canvas·DOM은 VM에서 대체된다. 이번 감사에는 실제 브라우저 화면, 실제 iOS/Android 기기, 배포 실행 검증을 포함하지 않았다. 아래 화면·터치 검증은 다음 PR의 완료 조건이다.

## 다음 PR의 범위와 구현 순서

권장 제목: **feat: 포획·판매·장비 성장과 하트·게임오버 흐름 완성**

완성할 사용자 흐름은 두 가지다.

1. 잠수/낚시로 포획 → 수족관에서 재고 확인·판매 → 코인으로 장비 구매 → 효과 적용 → 저장 후 재접속.
2. 상어 충돌 → 하트 감소/상자 회복 → 체력 소진 → 게임오버 → 기록을 보존한 재시작.

아래 수치와 키 배치는 이번 작업에서 적용한 정책이다. PR #1의 단축키 제안에 대한 추가 댓글·승인 기록은 없으므로 확정된 과거 결정으로 취급하지 않는다.

### 1. 포획 재고·판매·기존 저장 복구

변경 위치: `site/assets/js/game.js`의 `emptySave`, `normalizeSave`, `stockAquarium`, `markCaught`, `caught`; `tests/game.test.cjs` 또는 별도 `tests/economy.test.cjs`.

- [x] `markCaught()`에서 일반 포획은 `hold`, 희귀 포획은 `holdR`에 정확히 1마리씩 추가한다. 작살과 낚시 모두 같은 경로를 사용한다.
- [x] 재고와 누적 기록을 분리한다. 판매는 재고·코인만 바꾸고 `caught/rare/seen/at/titles`와 트로피 진행은 보존한다.
- [x] 종·일반/희귀·수량을 받는 판매 처리와 전체 판매 처리를 만들고 기존 `priceOf()`를 사용한다. 수량은 양의 정수이며 재고 이하만 허용하고, 취소·빈 재고·중복 입력은 지급하지 않는다. 코인 합계도 안전한 정수 범위를 유지한다.
- [x] 관찰만 가능한 상어/메갈로돈의 희귀 기록을 판매 가능한 포획으로 취급하지 않는다. 저장 검증에서는 기록을 보존하고 재고에 대해서만 포획 가능한 종과 수량을 제한한다.
- [x] **현 main의 `stocked=1` 저장도 고려한다.** `markCaught()` 수정만으로 이미 빠진 재고는 돌아오지 않는다. 현 main에는 판매 기능이 없으므로, 이 버전이 만든 저장은 새 경제 기능 마이그레이션 표식(예: `economyVersion: 1`)이 없을 때 누적 포획으로 재고를 한 번 복원하는 정책을 권장한다. 일반은 `max(0, caught - rare)`, 희귀는 `min(caught, rare)`를 포획 가능한 종에만 적용하고 코인·장비·기록은 유지한다.
- [x] 새 표식은 `emptySave`/`normalizeSave`/저장에 함께 반영하되, 구형 입력에 표식이 없다는 사실을 마이그레이션 전에 잃지 않는다. 마이그레이션 완료 표식과 재고를 함께 저장한다. 이후 판매한 재고를 로딩 때 다시 채우지 않는 회귀 테스트를 추가한다. 이 복구 정책의 대상은 **이 저장소의 현 main이 생성한 저장**이다.
